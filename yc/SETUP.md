# Настройка Yandex Cloud для формы ArtKull

Все шаги — в консоли https://console.yandex.cloud. Значения из таблицы ниже
подставляйте по мере получения.

| Что                   | Где взять                  | Значение                                                    |
| --------------------- | -------------------------- | ----------------------------------------------------------- |
| Folder ID             | консоль, каталог           | b1g7vmkqn5phq8qul45t                                        |
| Function ID           | после создания функции     | d4e05gt0g52ifsid0a29                                        |
| Служебный домен шлюза | после создания API Gateway | https://d5d5pjkjrtb9g3ke7kfs.6brbn2wz.apigw.yandexcloud.net |

## 1. Каталог и биллинг

1. Войдите в консоль, выберите облако и создайте/выберите каталог
   (например `artkull`). Скопируйте **Folder ID**.
2. Если платёжный аккаунт не привязан — привяжите. Бесплатных лимитов хватает,
   но аккаунт нужен.

## 2. Сервисный аккаунт

1. `IAM` → **Сервисные аккаунты** → **Создать**.
2. Имя: `artkull-form-gateway`.
3. Добавьте роль `functions.invoke`.
4. Создайте.
5. Скопируйте **ID** сервисного аккаунта (вида `aje...`) — он нужен
   в спецификации шлюза (шаг 4).

## 2.1. Бот MAX: токен и получатель

MAX Bot API доступен только с верифицированным профилем (самозанятый/ИП) на
платформе «MAX для партнёров».

1. Подключитесь к [платформе MAX для партнёров](https://business.max.ru/self),
   создайте и верифицируйте профиль (самозанятый/ИП).
2. Создайте чат-бота: раздел **Чат-боты** → **Создать**. Дождитесь модерации
   (до 48 часов) — до этого бота нельзя найти в MAX.
3. Получите **токен бота**: карточка бота → **⋮** → **Настройки** → скопировать
   токен. Это значение для `MAX_TOKEN`.
4. Запустите бота из своего аккаунта MAX (найдите по никнейму → **Начать**),
   затем найдите свой **user_id**:

   ```bash
   curl -s "https://platform-api2.max.ru/updates" -H "Authorization: <MAX_TOKEN>"
   ```

   В полученных обновлениях найдите `user.user_id` — это `MAX_USER_ID`.
   (Запрос делается с корневым сертификатом Минцифры; если `curl` ругается на
   сертификат, используйте браузер или добавьте `--cacert`.)

Корневой сертификат Минцифры уже лежит в `yc/form/certs/` и попадает в ZIP —
функция использует его для TLS через `MAX_CA_PATH`.

## 3. Функция

1. `Cloud Functions` → **Создать функцию**, имя `artkull-form`.
2. `Создать версию`:
   - Среда выполнения: **Node.js 18**.
   - Способ загрузки: **ZIP-архив** — соберите командой
     `powershell -ExecutionPolicy Bypass -File yc/form/build-zip.ps1`
     (подробности в `yc/form/README.md`).
   - Точка входа: `index.handler`.
   - Таймаут: `10` секунд, память: `128 МБ`.
   - Переменные окружения:
     - `MAX_TOKEN` = токен бота MAX (включите отметку «секрет») — см. 2.1;
     - `MAX_USER_ID` = ваш user_id в MAX — см. 2.1;
     - `MAX_CA_PATH` = `/function/code/certs/russian_trusted_root_ca.pem`;
     - `TURNSTILE_SECRET` = секрет виджета Turnstile (включите отметку «секрет»);
     - `TURNSTILE_HOSTNAMES` = `artkull.ru` (allowlist hostname через запятую);
     - `TURNSTILE_ACTION` = `contact`;
     - `ALLOWED_ORIGIN` = `https://artkull.ru`;
     - `DRY_RUN` = `true` (на время настройки);
     - `RATE_MAX` = `5`;
     - `RATE_WINDOW` = `600`.
   - Создайте версию.
3. Скопируйте **Function ID**.
4. Убедитесь, что публичный доступ к функции **не** включён.
5. Вкладка «Тестирование»: вставьте JSON-событие (метод и тело) и запустите.
   **После включения Turnstile** консольный тест вернёт `403` и
   `{"ok":false,"error":"turnstile_failed"}` — у события нет валидного токена
   `cf-turnstile-response`. Это ожидаемо; реальную отправку проверяйте через
   сайт (раздел 7). До включения Turnstile тест возвращал `200` и
   `{"ok":true}`:

   ```json
   {
     "requestContext": { "http": { "method": "POST" }, "identity": { "sourceIp": "1.2.3.4" } },
     "headers": { "accept": "application/json" },
     "body": "name=Тест&contact=test@example.com"
   }
   ```

## 4. API Gateway

1. `API Gateway` → **Создать**, имя `artkull-form-gw`.
2. Вставьте спецификацию из `yc/gateway/openapi.yaml`, заменив
   `<FUNCTION_ID>` на ID из шага 3 и `<SERVICE_ACCOUNT_ID>` на ID
   сервисного аккаунта из шага 2.
3. Сервисный аккаунт задаётся именно в спецификации
   (`service_account_id` в интеграции). Если в шлюзе включён публичный вызов
   функции, строка не нужна; для приватной функции она обязательна, иначе
   запрос вернёт `403 Forbidden`.
4. Обработку CORS (preflight `OPTIONS`) шлюз делает сам по блоку
   `x-yc-apigateway.cors` в спецификации. Ограничение скорости (`rateLimit`)
   в спецификации YC помечено устаревшим — лимит обеспечивает сама функция
   (в памяти), при необходимости позже подключите Smart Web Security.
5. Создайте шлюз. Скопируйте **служебный домен** вида
   `xxxxxxxx.apigw.yandexcloud.net`.
6. Проверьте:

   ```bash
   curl -i -X POST https://<служебный-домен>/ \
     -H "Content-Type: application/x-www-form-urlencoded" \
     --data "name=Тест&contact=test@example.com"
   ```

   Ожидается `200` и `{"ok":true}`.

## 5. Сертификат

1. `Certificate Manager` → **Выпустить сертификат** → Let's Encrypt.
2. Домен: `api.artkull.ru`.
3. Способ проверки: **DNS-валидация**. Консоль покажет CNAME-запись
   подтверждения:
   - **Имя:** `_acme-challenge.api.artkull.ru`
   - **Значение:** вида `xxxxxxxxxxxx.cm.yandexcloud.net`
4. Добавьте эту запись в DNS у регистратора домена `artkull.ru`.
   **Имя должно быть `_acme-challenge.api`, а не `api`** — запись на `api`
   валидацию не проходит.

   В Beget DNS-записи привязаны к подзоне, отдельного поля «Имя» нет:
   1. `DNS` → выберите домен `artkull.ru` → **Добавить подзону**.
   2. Введите полное имя подзоны `_acme-challenge.api.artkull.ru` → сохранить.
   3. Откройте подзону на редактирование и добавьте запись типа **CNAME**
      со значением из шага 3 (без точки на конце).
5. Дождитесь статуса сертификата **Issued** (обычно от пары минут).

## 6. Домен для API Gateway

1. Убедитесь, что сертификат из шага 5 в статусе **Issued**.
2. `API Gateway` → ваш шлюз → вкладка **Домены** → **Добавить**: выберите
   сертификат из шага 5 и введите FQDN `api.artkull.ru`.
3. У регистратора добавьте CNAME-запись для домена на служебный домен шлюза:

   ```text
   api.artkull.ru IN CNAME <служебный_домен_API-шлюза>
   ```

   Служебный домен виден на странице шлюза в поле «Служебный домен»
   (`xxxxxxxx.apigw.yandexcloud.net`). Имена должны заканчиваться точкой.

   В Beget: в подзоне `api.artkull.ru` удалите A-запись (по умолчанию Beget
   ставит туда IP хостинга) и добавьте **CNAME** со служебным доменом шлюза.
   A- и CNAME-записи с одним именем сосуществовать не могут.

4. **Альтернатива (сложнее):** делегировать поддомен в Cloud DNS и создать
   ANAME-запись. Для этого у регистратора нужны NS-записи
   `api.artkull.ru` → `ns1.yandexcloud.net`, `ns2.yandexcloud.net`.
   Для `api.artkull.ru` (домен третьего уровня) достаточно варианта с CNAME
   из шага 3 — отдельная зона Cloud DNS не нужна.

5. Дождитесь применения DNS и проверьте:

   ```bash
   curl -i -X POST https://api.artkull.ru/ \
     -H "Content-Type: application/x-www-form-urlencoded" \
     -H "Accept: application/json" \
     --data "name=Тест&contact=test@example.com"
   ```

   Ожидается `200` и `{"ok":true}`.

## 7. Боевой тест

1. В функции измените `DRY_RUN` на `false`, создайте новую версию.
2. Откройте `https://artkull.ru/`, отправьте тестовую заявку.
3. Убедитесь, что сообщение пришло вам в MAX от бота, а на сайте показан успех.
4. Проверьте негативный сценарий: пустые поля → инлайн-ошибка; частые отправки →
   сообщение о лимите.

## 8. Обновление кода функции

Повторите сборку ZIP и создайте новую версию функции (измените `DRY_RUN` обратно
при необходимости). Шлюз и домен менять не нужно.
